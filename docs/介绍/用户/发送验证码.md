# 发送验证码 — SmsCode

## 功能概述

向指定手机号发送 6 位短信验证码，用于注册和登录场景。该接口通过 **Redis 双 Key 机制**（验证码 Key + 频率锁 Key）实现验证码的存储与防刷限流，并调用**阿里云 DYPNS（号码认证服务）**完成短信的实际下发。

## 路由信息

```
POST /v1/user/sms
```

中间件链：`TreaceLoggerMiddleware` → `SmsCodeHandler`（无 AuthHttpMiddleware）

## 完整实现流程

### 1. 中间件阶段

仅经过全局的 `TreaceLoggerMiddleware`，为请求生成唯一 `traceID`（UUID v4），注入 `context` 用于全链路日志追踪。

此接口无需登录态，不经过 Auth 认证中间件。

### 2. Handler 层 — 参数绑定

从请求体中 JSON 绑定 `SmsCodeRequest` 结构体：

```go
type SmsCodeRequest struct {
    Telephone string `json:"telephone" binding:"required"`
}
```

绑定失败时返回 `400001 — 请求格式错误`。

### 3. Service 层 — 验证码发送（五步操作）

`userService.SmsCodeService` 按顺序执行以下步骤：

#### 步骤一：手机号格式校验

```go
tools.IsPhone(req.Telephone)
```

使用正则 `^1[3456789]\d{9}$` 校验手机号是否为合法的 11 位中国大陆手机号。

- 格式不合法 → 返回 `400002 — 手机号格式错误`

#### 步骤二：频率限制检查

```go
lockExist, err := u.redisClient.Exists(ctx, "verify:lock:" + req.Telephone).Result()
```

查询 Redis 中是否存在该手机号的频率锁 Key。锁 Key 由上一次成功发送时写入，TTL 为 60 秒。

- 锁 Key 存在 → 距上次发送不足 60 秒 → 返回 `400003 — 发送太频繁，请稍后再试`
- Redis 查询异常 → 返回 `500001 — 发送验证码失败:系统繁忙`
- 锁 Key 不存在 → 继续

#### 步骤三：生成 6 位随机验证码

```go
max := big.NewInt(1000000)
smsCode, err := rand.Int(rand.Reader, max)
```

使用 `crypto/rand` 生成密码学安全的随机数（范围 0 ~ 999999），转为字符串作为验证码。

#### 步骤四：Redis Pipeline 写入双 Key

```go
pipe := u.redisClient.Pipeline()
pipe.Set(ctx, "verify:code:" + req.Telephone, smsCodeStr, 300 * time.Second)
pipe.Set(ctx, "verify:lock:" + req.Telephone, "1", 60 * time.Second)
_, err = pipe.Exec(ctx)
```

通过 Redis Pipeline 一次性写入两个 Key：

| Key | Value | TTL | 用途 |
|-----|-------|-----|------|
| `verify:code:{手机号}` | 验证码明文 | 300 秒（5 分钟） | 注册/登录时校验 |
| `verify:lock:{手机号}` | `"1"` | 60 秒 | 防止 60 秒内重复发送 |

Pipeline 保证两个写操作原子性提交，减少网络往返。

#### 步骤五：调用阿里云发送短信

```go
tools.SendTelephoneCode(u.aliAccessConfig, args, smsCodeStr)
```

调用阿里云 DYPNS `SendSmsVerifyCode` 接口发送短信，参数包括：

| 参数 | 值 | 说明 |
|------|----|------|
| SignName | `"速通互联验证服务"` | 短信签名 |
| PhoneNumber | 用户手机号 | 接收方 |
| TemplateCode | `"100001"` | 阿里云短信模板编号 |
| TemplateParam | `{"code":"xxx","min":"5"}` | 模板变量（验证码 + 有效期） |

阿里云 SDK 使用 `AliAccessConfig` 中的 AccessKey/SecretKey 创建客户端：

```go
credentialsConfig := new(credentials.Config).
    SetType("access_key").
    SetAccessKeyId(configs.AccessKey).
    SetAccessKeySecret(configs.SecretKey)
```

- 发送成功 → 返回 `200 — 发送验证码成功`
- 发送失败 → **回滚**删除刚写入的 Redis 双 Key，避免留下脏数据 → 返回 `500001`

## 验证码的消费流程

验证码写入 Redis 后，在注册和登录接口中被消费：

```go
func VerifyCode(c context.Context, verifyCode, key string, redisClient *redis.Client) (int, error) {
    smsCode, err := redisClient.Get(c, key).Result()
    // redis.Nil → 验证码过期或不存在
    // smsCode != verifyCode → 验证码错误
    // 校验通过 → redisClient.Del(c, key) → 一次性消费
    return 0, nil
}
```

验证码校验通过后立即从 Redis 中删除，实现**一次性消费**，防止重放攻击。

## 核心设计

| 设计点 | 说明 |
|--------|------|
| Redis 双 Key | 验证码 Key（5min）用于校验，锁 Key（60s）用于防刷，职责分离 |
| Pipeline 原子写入 | 两个 Key 通过 Pipeline 一次提交，减少网络往返 |
| 失败回滚 | 短信发送失败时主动 DEL 双 Key，避免用户被锁 60 秒却没收到验证码 |
| crypto/rand | 使用密码学安全随机数而非 math/rand，防止验证码被预测 |
| 阿里云 DYPNS | 通过阿里云号码认证服务发送，企业级短信通道保证到达率 |
| 一次性消费 | 验证码校验通过即删除，防止同一验证码被多次使用 |

## 调用链路图

```
Client
  │
  ├── Body: { "telephone": "13800138000" }
  │
  ▼
TreaceLoggerMiddleware   →  生成 traceID, 注入 context
  │
  ▼
UserHandler.SmsCode      →  ShouldBindJSON 绑定手机号
  │
  ▼
UserService.SmsCodeService
  │
  ├── [1] tools.IsPhone              →  正则校验手机号格式
  ├── [2] Redis EXISTS               →  verify:lock:{手机号} 频率检查
  ├── [3] crypto/rand                →  生成 6 位随机验证码
  ├── [4] Redis Pipeline SET×2       →  写入 verify:code + verify:lock
  └── [5] tools.SendTelephoneCode    →  阿里云 DYPNS 发送短信
          │
          ├── 成功 → 返回 200
          └── 失败 → Redis DEL 双 Key（回滚）→ 返回 500001
  │
  ▼
JsonBack                 →  { code: 200, msg: "发送验证码成功" }
```

## 涉及的 Redis Key

| Key | 操作 | TTL | 说明 |
|-----|------|-----|------|
| `verify:code:{手机号}` | SET（本接口写入） | 300 秒 | 验证码明文，注册/登录时 GET 校验 |
| `verify:lock:{手机号}` | SET（本接口写入） | 60 秒 | 频率锁，60 秒内阻止重复发送 |
| `verify:code:{手机号}` | DEL（校验通过后删除） | — | 一次性消费，防重放 |
| 双 Key | DEL（发送失败时回滚） | — | 避免用户被锁却没收到验证码 |
