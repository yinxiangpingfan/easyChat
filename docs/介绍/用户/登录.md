# 登录 — Login

## 功能概述

已注册用户通过**密码登录**或**短信验证码登录**两种方式获取系统访问权限。登录成功后签发 AccessToken + RefreshToken 双 Token，并将 RefreshToken 写入 Redis 用于后续续签。同时更新用户的最后登录时间。

## 路由信息

```
POST /v1/user/login
```

中间件链：`TreaceLoggerMiddleware` → `LoginHandler`（无 AuthHttpMiddleware）

## 完整实现流程

### 1. 中间件阶段

仅经过全局的 `TreaceLoggerMiddleware`，为请求生成唯一 `traceID`（UUID v4），注入 `context` 用于全链路日志追踪。

此接口面向未登录用户，不经过 Auth 认证中间件。

### 2. Handler 层 — 参数绑定

从请求体中 JSON 绑定 `LoginRequest` 结构体：

```go
type LoginRequest struct {
    LoginType string `json:"login_type" binding:"required,oneof=password sms_code"`
    Phone     string `json:"phone" binding:"required"`
    Password  string `json:"password" binding:"required_if=LoginType password"`
    Code      string `json:"code" binding:"required_if=LoginType sms_code"`
}
```

| 字段 | 必填条件 | 说明 |
|------|----------|------|
| login_type | 始终必填，值为 `"password"` 或 `"sms_code"` | 登录方式选择 |
| phone | 始终必填 | 手机号 |
| password | 当 login_type = `"password"` 时必填 | 密码 |
| code | 当 login_type = `"sms_code"` 时必填 | 短信验证码 |

`oneof` 约束确保 login_type 只能是两种合法值之一；`required_if` 实现条件必填，即密码登录时不需要传验证码，反之亦然。

绑定失败时返回 `400001 — 参数校验失败:登录请求参数错误`。

### 3. Service 层 — 登录执行（六步操作）

`userService.LoginService` 按顺序执行以下步骤：

#### 步骤一：手机号格式校验

```go
tools.IsPhone(req.Phone)
```

使用正则 `^1[3456789]\d{9}$` 校验手机号格式。

- 格式不合法 → 返回 `400002 — 手机号格式错误`

#### 步骤二：查询用户记录

```go
user, err := u.userRepo.GetUserByPhone(ctx, req.Phone)
```

通过 GORM 按 `telephone` 查询 `user_info` 表：

- 查询出错 → 返回 `500001 — 登录失败，请稍后重试`
- 用户不存在（`ErrRecordNotFound`）→ 返回 `400003 — 用户不存在`
- 查到用户 → 继续

#### 步骤三：身份验证（分支逻辑）

根据 `login_type` 执行不同的验证逻辑：

**分支 A — 密码登录（login_type = "password"）：**

```go
hashedPassword := tools.PasswordHash(req.Password, user.Salt)
if hashedPassword != user.Password { ... }
```

取数据库中该用户的 `salt`，将客户端提交的明文密码 + salt 进行 MD5 哈希，与数据库存储的哈希值比对。

- 不一致 → 返回 `400004 — 密码错误`
- 一致 → 继续

**分支 B — 验证码登录（login_type = "sms_code"）：**

```go
if len(req.Code) != 6 { ... }
code, err := tools.VerifyCode(ctx, req.Code, "verify:code:" + req.Phone, u.redisClient)
```

先检查验证码是否为 6 位，然后从 Redis 中取出 `verify:code:{手机号}` 对应的验证码进行比对：

- 长度不为 6 → 返回 `400001 — 请求格式错误`
- 验证码错误或已过期 → 返回 `400005 — 验证码错误或已过期`
- 校验通过 → 从 Redis 删除验证码（一次性消费）→ 继续

#### 步骤四：封禁状态检查

```go
if user.Status == 1 { ... }
```

检查数据库中用户的 `status` 字段：

- `status == 1`（禁用）→ 返回 `400006 — 用户已被禁用`
- `status == 0`（正常）→ 继续

#### 步骤五：签发双 Token + Redis 存储

```go
accessToken, refreshToken, err := tools.GenerateAccessToken(u.jwtConfig, user.Uuid, user.Telephone, user.IsAdmin)
```

生成一对 JWT Token：

| Token | 签名密钥 | 有效期 | Claims |
|-------|---------|--------|--------|
| AccessToken | `AccessSecret` | 15 分钟 | uuid, telephone, is_admin |
| RefreshToken | `RefreshSecret` | 168 小时（7 天） | uuid, telephone, is_admin |

将 RefreshToken 写入 Redis：

```go
u.redisClient.Set(ctx, "refreshToken:" + user.Uuid, refreshToken, 168 * time.Hour)
```

Redis 中存储 RefreshToken 的目的：
- 刷新 Token 接口校验 RefreshToken 的合法性时需要检查 Redis 中是否存在
- 封禁用户时删除该 Key 可以立即阻止用户续签
- 每次登录覆盖旧值，实现单设备登录效果（同一用户只有最新的 RefreshToken 有效）

#### 步骤六：更新最后登录时间

```go
u.userRepo.UpdateLastOnlineAt(ctx, user.Uuid)
```

```go
db.Model(&model.UserInfo{}).Where("uuid = ?", uuid).Update("last_online_at", time.Now())
```

更新 `user_info` 表的 `last_online_at` 字段为当前时间。此操作即使失败也不影响登录结果（仅记录 error 日志，不返回错误）。

### 4. 响应结构

```go
type LoginResp struct {
    Uuid         string `json:"uuid"`
    NickName     string `json:"nick_name"`
    Telephone    string `json:"telephone"`
    AccessToken  string `json:"access_token"`
    RefreshToken string `json:"refresh_token"`
}
```

返回 `200 — 登录成功`，携带用户基本信息和双 Token。客户端需保存 AccessToken 用于后续请求鉴权，保存 RefreshToken 用于 AccessToken 过期后的续签。

## 双登录方式对比

| 维度 | 密码登录 | 验证码登录 |
|------|----------|------------|
| login_type | `"password"` | `"sms_code"` |
| 验证凭据 | password 字段 | code 字段 |
| 验证方式 | MD5(密码 + salt) 与数据库比对 | Redis 中验证码比对 |
| 前置条件 | 注册时已设置密码 | 需先调用 /sms 获取验证码 |
| 验证码消费 | 不涉及 | 校验通过后从 Redis 删除 |

## 核心设计

| 设计点 | 说明 |
|--------|------|
| 双登录方式 | 密码 + 验证码两种方式，通过 `login_type` 字段分支处理 |
| 条件必填 | `required_if` 标签实现参数的条件验证，减少无效请求 |
| 加盐哈希比对 | 密码登录时用数据库中的 salt 重新计算哈希，而非存储明文 |
| 验证码一次性消费 | 验证码校验通过后立即从 Redis 删除，防止重放 |
| 封禁前置检查 | 身份验证通过后、签发 Token 前检查封禁状态，防止被封用户获取 Token |
| RefreshToken 持久化 | 写入 Redis 绑定 UUID，支持封禁时即时失效、刷新时合法性校验 |
| 单设备覆盖 | 同一用户重复登录时 Redis 中的 RefreshToken 被覆盖，旧 Token 失效 |
| 登录时间记录 | 更新 last_online_at，异步容错（失败不影响登录） |

## 调用链路图

```
Client
  │
  ├── Body (密码登录): { "login_type": "password", "phone": "13800138000", "password": "abc123" }
  ├── Body (验证码登录): { "login_type": "sms_code", "phone": "13800138000", "code": "123456" }
  │
  ▼
TreaceLoggerMiddleware   →  生成 traceID, 注入 context
  │
  ▼
UserHandler.Login        →  ShouldBindJSON 绑定参数（含条件必填校验）
  │
  ▼
UserService.LoginService
  │
  ├── [1] tools.IsPhone              →  正则校验手机号格式
  ├── [2] userRepo.GetUserByPhone    →  MySQL 查询用户记录
  │
  ├── [3] 身份验证（二选一）
  │       ├── password 方式  →  tools.PasswordHash(密码, salt) 比对数据库哈希
  │       └── sms_code 方式  →  tools.VerifyCode(Redis GET + 比对 + DEL)
  │
  ├── [4] user.Status 检查           →  封禁状态判断
  ├── [5] tools.GenerateAccessToken  →  签发 AccessToken + RefreshToken
  │       └── Redis SET              →  refreshToken:{uuid} (TTL 7天)
  └── [6] userRepo.UpdateLastOnlineAt →  更新最后登录时间（容错）
  │
  ▼
JsonBack                 →  { code: 200, msg: "登录成功", data: { uuid, nick_name, telephone, access_token, refresh_token } }
```

## 涉及的 Redis Key

| Key | 操作 | TTL | 说明 |
|-----|------|-----|------|
| `verify:code:{手机号}` | GET + DEL（验证码登录时消费） | 300 秒 | 验证码校验后一次性删除 |
| `refreshToken:{uuid}` | SET（登录成功时写入） | 168 小时 | 续签校验 + 封禁失效 + 单设备覆盖 |
