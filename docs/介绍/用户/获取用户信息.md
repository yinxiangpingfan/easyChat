# 获取用户信息 — GetUserInfo

## 功能概述

已登录用户通过有效的 AccessToken 获取自身的完整个人资料。该接口采用 **Redis 缓存 + MySQL 兜底** 的两级读取策略，缓存命中时直接返回，未命中则查数据库并回填缓存，有效降低数据库访问压力。

## 路由信息

```
GET /v1/user/getUserInfo
```

中间件链：`TreaceLoggerMiddleware` → `AuthHttpMiddleware` → `GetUserInfoHandler`

## 完整实现流程

### 1. 中间件鉴权阶段

#### 1.1 TraceLogger 中间件

为每个请求生成一个唯一的 `traceID`（UUID v4），绑定到 `logrus.Entry` 后注入 `context`，后续所有日志均可追踪到该请求。

#### 1.2 Auth 认证中间件

- 从 `Authorization: Bearer <token>` 请求头中提取 AccessToken
- 使用 `HS256` + `AccessSecret` 对 JWT 进行解析和签名校验
- 从 Claims 中提取 `uuid`、`telephone`、`is_admin` 三个字段
- `is_admin` 映射规则：`0` → `"user"`, `1` → `"admin"`, `2` → `"superAdmin"`
- **封禁检查**（二级缓存策略）：
  - **L1 — go-cache**：以 `uuid` 为 key 查询本地缓存，值为 `"banned"` 则直接拒绝，值为 `"normal"` 则放行
  - **L2 — Redis**：若 L1 未命中，查询 `bannedUUID:{uuid}` 是否存在；存在则写入 go-cache（TTL 15min）后拒绝
  - **缓存回填**：用户状态正常时，写入 go-cache（TTL 1min）避免后续请求重复查 Redis
- 校验通过后将 `uuid`、`tel`、`user`（角色字符串）挂载到 `gin.Context`

### 2. Handler 层 — 直接调用

本接口为 GET 请求，无需绑定请求体，Handler 直接调用 Service：

```go
func (u *userHandler) GetUserInfoHandler() gin.HandlerFunc {
    return func(c *gin.Context) {
        code, message, data, ret := u.userService.GetUserInfoService(c)
        JsonBack(c, code, message, data, ret)
    }
}
```

用户身份信息（uuid 等）已由中间件注入到 `gin.Context` 中，Service 层直接从 Context 读取。

### 3. Service 层 — 两级读取策略

`userService.GetUserInfoService` 按以下优先级获取数据：

#### 步骤一：从 Redis 缓存读取

```go
cachedData, err := u.redisClient.Get(ctx, "user:info:" + uuid).Result()
```

缓存 key 格式为 `user:info:{uuid}`，若命中则 JSON 反序列化为 `UserInfoResp` 直接返回。

#### 步骤二：缓存未命中，查数据库

```go
user, err := u.userRepo.GetUserInfo(ctx, uuid)
```

通过 GORM 按 `uuid` 条件查询 `user_info` 表，获取完整的用户记录。

- 查询失败 → 返回 `500001 — 系统繁忙`
- 查到 `ErrRecordNotFound` → 返回 "用户不存在" 错误

#### 步骤三：组装响应 + 写入缓存

```go
userInfo := resp.UserInfoResp{
    Uuid:          user.Uuid,
    NickName:      user.NickName,
    Telephone:     user.Telephone,
    Email:         user.Email,
    Avatar:        user.Avatar,
    Signature:     user.Signature,
    Birthday:      user.Birthday,
    LastOnlineAt:  user.LastOnlineAt,
    LastOfflineAt: user.LastOfflineAt,
}
```

将组装好的 `UserInfoResp` JSON 序列化后写入 Redis：

```go
u.redisClient.Set(ctx, cacheKey, string(data), 30 * time.Minute)
```

缓存 TTL 为 **30 分钟**，在此期间的重复请求直接走缓存返回。

### 4. 响应结构

```go
type UserInfoResp struct {
    Uuid          string
    NickName      string
    Telephone     string
    Email         string
    Avatar        string
    Signature     string
    Birthday      string
    LastOnlineAt  *time.Time
    LastOfflineAt *time.Time
}
```

| 字段 | 说明 |
|------|------|
| Uuid | 用户唯一标识 |
| NickName | 昵称 |
| Telephone | 手机号 |
| Email | 邮箱 |
| Avatar | 头像 URL（默认：阿里云 OSS 默认头像） |
| Signature | 个性签名 |
| Birthday | 生日 |
| LastOnlineAt | 最后在线时间 |
| LastOfflineAt | 最近离线时间 |

## 缓存一致性保证

本接口的缓存通过 **Cache-Aside 模式** 保证与数据库的一致性：

```
读取流程：
  Cache HIT   →  直接返回缓存数据
  Cache MISS  →  查 DB → 写入缓存 → 返回

写入流程（更新用户信息接口）：
  更新 DB → 主动 DEL user:info:{uuid}
  下次查询时 Cache MISS → 从 DB 重新加载最新数据
```

## 核心设计

| 设计点 | 说明 |
|--------|------|
| Redis 缓存 30 分钟 | 个人信息更新频率低，缓存 30 分钟可以大幅减少 DB 查询 |
| Cache-Aside 模式 | 更新时主动删缓存（由更新用户信息接口负责），避免脏数据 |
| 封禁检查在中间件 | 被封禁用户在 Auth 中间件阶段即被拦截，不会到达 Service 层 |
| 无请求体 | GET 请求，用户身份完全通过 JWT → Context 传递，接口简洁 |
| 敏感字段过滤 | 响应体不包含 password、salt 等敏感信息，仅返回展示所需字段 |

## 调用链路图

```
Client
  │
  ├── Authorization: Bearer <AccessToken>
  │
  ▼
TreaceLoggerMiddleware   →  生成 traceID, 注入 context
  │
  ▼
AuthHttpMiddleware       →  JWT 解析 + 封禁检查(go-cache → Redis)
  │                          挂载 uuid / tel / user 到 Context
  ▼
UserHandler.GetUserInfo  →  直接调用 Service（无参数绑定）
  │
  ▼
UserService.GetUserInfoService
  │
  ├── [1] Redis GET user:info:{uuid}
  │       ├── 命中 → JSON 反序列化 → 直接返回
  │       └── 未命中 ↓
  │
  ├── [2] userRepo.GetUserInfo(uuid) → MySQL 查询
  │
  └── [3] Redis SET user:info:{uuid} (TTL 30min) → 回填缓存
  │
  ▼
JsonBack                 →  { code: 0, msg: "", data: { UserInfoResp } }
```

## 涉及的 Redis Key

| Key | 操作 | TTL | 说明 |
|-----|------|-----|------|
| `user:info:{uuid}` | GET（本接口读取） | 30 分钟 | 用户信息缓存 |
| `user:info:{uuid}` | SET（本接口回填） | 30 分钟 | 缓存未命中时写入 |
| `user:info:{uuid}` | DEL（更新接口清除） | — | 用户信息变更时主动失效 |
| `bannedUUID:{uuid}` | EXISTS（中间件检查） | 永久 | 封禁状态标记 |
