# 获取用户列表 — GetUserInfoList

## 功能概述

管理员分页查询系统中所有用户的基本信息，用于后台用户管理面板展示。该接口仅限管理员角色（`admin` / `superAdmin`）访问。

## 路由信息

```
GET /v1/admin/getUserInfoList
```

中间件链：`TreaceLoggerMiddleware` → `AuthHttpMiddleware` → `CheckAdminMiddleware` → `GetUserInfoList Handler`

## 完整实现流程

### 1. 中间件鉴权阶段

#### 1.1 TraceLogger 中间件

为每个请求生成一个唯一的 `traceID`（UUID v4），绑定到 `logrus.Entry` 后注入 `context`，后续所有日志均可追踪到该请求。

#### 1.2 Auth 认证中间件

- 从 `Authorization: Bearer <token>` 请求头中提取 AccessToken
- 使用 `HS256` + `AccessSecret` 对 JWT 进行解析和签名校验
- 从 Claims 中提取 `uuid`、`telephone`、`is_admin` 三个字段
- `is_admin` 映射规则：`0` → `"user"`, `1` → `"admin"`, `2` → `"superAdmin"`
- **封禁检查**（二级缓存策略）：
  - **L1 — go-cache**：以 `uuid` 为 key 查询本地缓存，值为 `"banned"` 则直接拒绝，值为 `"normal"` 则放行
  - **L2 — Redis**：若 L1 未命中，查询 `bannedUUID:{uuid}` 是否存在；存在则写入 go-cache（TTL 15min）后拒绝
  - **缓存回填**：用户状态正常时，写入 go-cache（TTL 1min）避免后续请求重复查 Redis
- 校验通过后将 `uuid`、`tel`、`user`（角色字符串）挂载到 `gin.Context`

#### 1.3 CheckAdmin 中间件

从 `gin.Context` 中取 `user` 值，仅 `"admin"` 或 `"superAdmin"` 放行，否则 `Abort` 终止请求。

### 2. Handler 层 — 参数绑定

从请求体中 JSON 绑定 `UserInfoListRequest` 结构体：

```go
type UserInfoListRequest struct {
    Page     int `json:"page" binding:"required"`
    PageSize int `json:"page_size" binding:"required"`
}
```

绑定失败时返回 `400001 — 请求格式错误`。

### 3. Service 层 — 业务处理

`adminServer.GetUserInfoList` 直接调用 Repository 层获取数据，不经过 Redis 缓存（管理后台数据需要实时性）。

若查询结果为空（`userList == nil`），返回空列表和 `total: 0`，而非报错。

查询成功后，遍历 `[]model.UserInfo` 转换为 `[]resp.UserInfoItem` 响应体，过滤掉敏感字段（如 `password`、`salt`）。

### 4. Repository 层 — 数据访问

分两步查询：

**第一步 — 统计总数：**

```go
db.WithContext(ctx).Model(&model.UserInfo{}).Count(&total)
```

**第二步 — 分页查询：**

```go
db.WithContext(ctx).
    Select("id", "uuid", "nickname", "telephone", "email", "avatar",
           "gender", "signature", "birthday", "created_at", "deleted_at",
           "last_online_at", "last_offline_at", "is_admin", "status").
    Scopes(gormscopes.Paginate(page, pageSize)).
    Find(&userList)
```

#### 分页实现 — `Paginate` Scope

```go
func Paginate(page, pageSize int) func(db *gorm.DB) *gorm.DB {
    // page <= 0 时重置为 1
    // pageSize 范围约束：(0, 100]，默认 10
    offset := (page - 1) * pageSize
    return db.Offset(offset).Limit(pageSize)
}
```

通过 GORM Scopes 机制注入分页逻辑，保持查询链的可组合性。

### 5. 响应结构

```go
type UserInfoListResponse struct {
    UserList []UserInfoItem `json:"user_list"`
    Total    int64          `json:"total"`
}
```

每个 `UserInfoItem` 包含：id、uuid、nickname、telephone、email、avatar、gender、signature、birthday、created_at、deleted_at、last_online_at、last_offline_at、is_admin、status。

## 核心设计

| 设计点 | 说明 |
|--------|------|
| 不使用 Redis 缓存 | 管理后台要求数据实时准确，直接走数据库 |
| Select 显式字段 | 避免返回 password、salt 等敏感字段 |
| 分页上限 100 | Paginate Scope 中硬编码上限，防止一次查询过多数据 |
| Count + Find 分离 | 总数和分页数据独立查询，保证 total 不受 Limit 影响 |

## 调用链路图

```
Client
  │
  ├── Authorization: Bearer <AccessToken>
  ├── Body: { "page": 1, "page_size": 10 }
  │
  ▼
TreaceLoggerMiddleware   →  生成 traceID, 注入 context
  │
  ▼
AuthHttpMiddleware       →  JWT 解析 + 封禁检查(go-cache → Redis)
  │
  ▼
CheckAdminMiddleware     →  校验角色为 admin / superAdmin
  │
  ▼
AdminHandler             →  ShouldBindJSON 绑定分页参数
  │
  ▼
AdminServer.GetUserInfoList  →  调用 repo, model → resp 转换
  │
  ▼
AdminRepository          →  Count(总数) + Scopes(Paginate).Find(分页查询)
  │
  ▼
JsonBack                 →  { code: 200, msg: "获取用户列表成功", data: { user_list, total }, ret: 0 }
```
