# 更新用户信息 — UpdateUserInfo

## 功能概述

已登录用户修改自身的个人资料（昵称、邮箱、性别、个性签名、生日）。采用**部分更新**策略，仅传入需要修改的字段即可，未传字段不受影响。更新成功后主动清除 Redis 缓存，保证下次查询获取到最新数据。

## 路由信息

```
POST /v1/user/updateUserInfo
```

中间件链：`TreaceLoggerMiddleware` → `AuthHttpMiddleware` → `UpdateUserInfoHandler`

## 完整实现流程

### 1. 中间件鉴权阶段

与「获取用户信息」一致，依次经过 TraceLogger、Auth 认证两个中间件。

#### 1.1 TraceLogger 中间件

为每个请求生成唯一 `traceID`（UUID v4），注入 `context` 用于全链路日志追踪。

#### 1.2 Auth 认证中间件

- 从 `Authorization: Bearer <token>` 请求头中提取 AccessToken
- JWT 签名校验 + 过期验证
- 封禁检查（go-cache L1 → Redis L2 二级缓存策略）
- 校验通过后将 `uuid`、`tel`、`user` 挂载到 `gin.Context`

### 2. Handler 层 — 参数绑定

从请求体中 JSON 绑定 `UpdateUserInfoRequest` 结构体：

```go
type UpdateUserInfoRequest struct {
    NickName  string `json:"nickname"`
    Email     string `json:"email"`
    Gender    string `json:"gender"`
    Signature string `json:"signature"`
    Birthday  string `json:"birthday"`
}
```

所有字段均**非必填**（无 `binding:"required"` 标签），客户端只传需要更新的字段。绑定失败（如 JSON 格式错误）时返回 `400001 — 请求格式错误`。

### 3. Service 层 — 部分更新（四步操作）

`userService.UpdateUserInfoService` 按顺序执行以下步骤：

#### 步骤一：从 Context 获取用户身份

```go
uuid := ctx.Value("uuid").(string)
```

用户的 `uuid` 由 Auth 中间件解析 JWT 后注入 Context，Service 层直接读取。

#### 步骤二：构建更新字段 Map

```go
updateFields := make(map[string]interface{})
if req.NickName != "" {
    updateFields["nickname"] = req.NickName
}
if req.Email != "" {
    updateFields["email"] = req.Email
}
// ... gender, signature, birthday 同理
```

遍历请求中的各字段，仅将**非空字符串**的字段加入 `updateFields`。这意味着：
- 客户端传了 `"nickname": "新昵称"` → 会更新
- 客户端未传 `nickname` 字段或传了 `""` → 不会更新

若所有字段均为空，直接返回成功（`200 — 更新用户信息成功`），不执行数据库操作。

#### 步骤三：执行数据库更新

```go
u.userRepo.UpdateUserInfo(ctx, uuid, updateFields)
```

Repository 层使用 GORM 的 `Updates()` 方法：

```go
db.WithContext(ctx).Model(&model.UserInfo{}).Where("uuid = ?", uuid).Updates(updateFields)
```

`Updates()` 只更新 map 中指定的列，其他列保持不变。

- 更新失败 → 返回 `500001 — 系统繁忙`

#### 步骤四：清除 Redis 缓存

```go
u.redisClient.Del(ctx, "user:info:" + uuid)
```

主动删除 `user:info:{uuid}` 缓存，保证下次调用「获取用户信息」接口时从数据库加载最新数据，与获取接口形成完整的 **Cache-Aside** 模式。

### 4. 响应结构

```go
type UpdateUserInfoResp struct {
    Uuid      string `json:"uuid"`
    Telephone string `json:"telephone,omitempty"`
    NickName  string `json:"nickname,omitempty"`
    Email     string `json:"email,omitempty"`
    Gender    string `json:"gender,omitempty"`
    Signature string `json:"signature,omitempty"`
    Birthday  string `json:"birthday,omitempty"`
}
```

返回体中包含本次请求提交的所有字段值（含空字符串），方便客户端确认提交内容。`omitempty` 标签使得未提交的字段不会出现在 JSON 响应中。

## 可更新字段

| JSON Key | 数据库列 | 类型 | 约束 |
|----------|----------|------|------|
| `nickname` | `nickname` | varchar(20) | 昵称 |
| `email` | `email` | char(30) | 邮箱 |
| `gender` | `gender` | tinyint | 性别（0 男 / 1 女） |
| `signature` | `signature` | varchar(100) | 个性签名 |
| `birthday` | `birthday` | char(8) | 生日 |

## 与获取用户信息接口的缓存协作

```
更新流程：
  Client POST { "nickname": "新昵称" }
    → DB UPDATE nickname = '新昵称' WHERE uuid = ?
    → Redis DEL user:info:{uuid}       ← 主动失效

后续读取：
  Client GET /getUserInfo
    → Redis GET user:info:{uuid}        ← MISS（已被删除）
    → DB SELECT ... WHERE uuid = ?      ← 获取最新数据
    → Redis SET user:info:{uuid}        ← 回填缓存（TTL 30min）
```

两个接口共同组成 Cache-Aside 模式：读时填充缓存，写时主动失效。

## 核心设计

| 设计点 | 说明 |
|--------|------|
| 部分更新 | 使用 `map[string]interface{}` + GORM `Updates()`，仅更新非空字段，避免全量覆盖 |
| 空更新容忍 | 所有字段均为空时不执行 SQL，直接返回成功，避免无意义的数据库操作 |
| 主动缓存失效 | 更新后立即 DEL Redis 缓存，保证缓存与数据库的最终一致性 |
| 非必填设计 | 所有字段均无 `required` 约束，支持灵活的单字段 / 多字段更新 |
| omitempty 响应 | 未提交的字段不出现在响应 JSON 中，响应体干净 |

## 调用链路图

```
Client
  │
  ├── Authorization: Bearer <AccessToken>
  ├── Body: { "nickname": "新昵称", "email": "new@example.com" }
  │
  ▼
TreaceLoggerMiddleware   →  生成 traceID, 注入 context
  │
  ▼
AuthHttpMiddleware       →  JWT 解析 + 封禁检查(go-cache → Redis)
  │                          挂载 uuid / tel / user 到 Context
  ▼
UserHandler.UpdateUserInfo  →  ShouldBindJSON 绑定更新字段
  │
  ▼
UserService.UpdateUserInfoService
  │
  ├── [1] ctx.Value("uuid")          →  获取用户身份
  ├── [2] 构建 updateFields map      →  收集非空字段
  ├── [3] userRepo.UpdateUserInfo    →  GORM Updates() 部分更新
  └── [4] Redis DEL                  →  删除 user:info:{uuid} 缓存
  │
  ▼
JsonBack                 →  { code: 200, msg: "更新用户信息成功", data: { UpdateUserInfoResp } }
```

## 涉及的 Redis Key

| Key | 操作 | 说明 |
|-----|------|------|
| `user:info:{uuid}` | DEL | 更新成功后主动删除缓存，触发下次读取时重新加载 |
